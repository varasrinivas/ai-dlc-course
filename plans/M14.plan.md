## Objectives

After this module, the learner can:

1. Describe what Claude Code loads at launch and the cascade: global (~/.claude/CLAUDE.md)
   → project CLAUDE.md → subdirectory CLAUDE.md files — most specific wins.
2. Write rules that steer: imperative, checkable, scoped — and recognize rules that
   don't (values posters, novels, per-bolt state).
3. Encode Prior Auth domain guardrails as steering rules an engine can actually obey
   and be caught violating.
4. Test steering: verify the engine restates rules and flags requests that conflict
   with them.

## Hook

Bolt 2 is about to start, and the team runs a drill before trusting the engine with the
scoring engine's guardrail: they ask Claude Code to "set the auto-approve cutoff to 0.7
while we test." The reply quotes CLAUDE.md back at them — the threshold is 0.85, changes
are a clinical policy decision requiring medical director sign-off, and it won't make
the edit without a decision record. The junior dev grins: "It just told the PO no." Not
quite — the *team* told the PO no, three weeks ago, when they wrote the rule. Steering
is the art of making your standards outrank your prompts.

## Concept outline

1. **What Claude Code reads, and when** (`<h2>`)
   - CLAUDE.md loads at launch, before any prompt — it outranks conversation by
     position; the session starts already knowing how this team builds.
   - The cascade: global ~/.claude/CLAUDE.md (personal defaults) → project root
     (team rules — in version control, reviewed like code) → subdirectory files
     (module-specific); most specific wins on conflict.
   - What belongs is M13's top layer verbatim: conventions, domain guardrails,
     workflow rules, pointers to knowledge artifacts (decisions.md, semantic map).
2. **Rules that steer** (`<h2>`)
   - Steering rules are imperative, checkable, and scoped: "Collect all validation
     errors; never fail-fast" can be obeyed and caught when violated. "Write clean
     code" cannot — a values poster, not a rule.
   - Domain guardrails as rules: the threshold rule (value + who may change it +
     what a change requires); PHI rules (no member data in logs, test fixtures
     synthetic-only); each carries its why in one clause when the why prevents
     misapplication.
   - Anti-patterns: novels (the engine reads it all — the humans won't), per-bolt
     state (wrong cadence, M13), duplicated knowledge (point to decisions.md, don't
     restate it).
3. **Enforcement in practice** (`<h2>`)
   - Steering vs prompting: a prompt asks once; a rule holds for every session and
     every teammate — if you've typed the same instruction three times, it's a rule.
   - Reusable workflows: .claude/commands/ turns multi-step rituals (plan-first
     construction, bolt close) into slash commands — this course kit itself is the
     worked example.
   - When rules collide or rot: conflicts surface as engine questions (good — it's
     deferring); staleness is fixed by reviewed edit, and the twin (AGENTS.md) gets
     the same edit or the fork bug from M13 arrives.
4. Note: hooks/permissions (mechanical enforcement) deliberately deferred to M17.

## Lab outline

**Lab M14 · 25 min · practitioner**

- **Path A — Understand It:** artifact = a flawed CLAUDE.md excerpt (8 lines: 3 values
  posters, 2 per-bolt entries, 1 duplicated knowledge line, 2 good rules). Trace: sort
  each line (keep / rewrite / relocate / delete); rewrite the three posters as steering
  rules. Check questions + answers.
- **Path B — Build It with AI (both engines):** unit of work — *harden the steering,
  then drill it*. (1) Engine adds three checkable guardrail rules to its steering file
  (threshold rule with authority + refusal path; PHI-in-logs rule; validation
  convention), mirroring the same edit to the twin file. (2) The drill: learner asks
  the engine to "set the auto-approve cutoff to 0.7 while we test" — engine must flag
  the conflict, quote the rule, and require a decision record. (3) Engine writes
  `docs/M14-steering-test.md`: the rules added + transcript summary of the refusal.
  - Claude Code variant edits CLAUDE.md (twin-syncs AGENTS.md); Codex variant mirrors.
  - Verify: twins agree; drill produced a refusal that quotes the rule; test log
    exists. Parity: same rules in both twins; refusal wording differs.
