## Objectives

After this module, the learner can:

1. Summarize the two engines' enforcement profiles honestly: Claude Code — mechanical
   gates (plan mode, hooks, native subagents); Codex — containment + warm review
   (sandbox, approval postures).
2. Choose an engine per task profile using the collected evidence (M15/M17/M18/M21
   asymmetries), not vibes or benchmarks.
3. Name the three run-both patterns — parity experiment, cross-engine review,
   split-by-class — and their tax (twin sync, doubled cost, drift risk).
4. Apply the lock-in test: could this team switch engines next bolt? If not, name
   which artifact is missing.

## Hook

The platform director finally asks the question the team has been collecting evidence
for: "Pick one engine — which?" And the team's answer, backed by ten modules of drill
logs, is that it's the wrong question twice over. Wrong once because selection is per
task profile, not per religion: the guardrail bolt wants the engine whose gates are
mechanical today; the demolition-week refactor wants the sandbox. Wrong twice because
the expensive asset was never the engine — it's the methodology living in files both
engines read. The team can switch engines next bolt and lose nothing but muscle
memory. That's not indecision. That's the whole point of how they built.

## Concept outline

1. **Two profiles, honestly stated** (`<h2>`)
   - Claude Code's edge is *mechanical enforcement*: plan mode (M15), hooks +
     permissions (M17), native subagent orchestration (M18) — gates that fire without
     anyone remembering.
   - Codex's edge is *containment + warm review*: the sandbox (M21), approval
     postures that make every change a proposal (M19), diff-first flow.
   - What benchmarks don't settle: model quality shifts monthly; mechanics and team
     fit persist — select on what you can verify in your own drill logs.
2. **Choosing per task profile** (`<h2>`)
   - Guardrail-class work → whichever engine has the rule *mechanized* today (M17's
     drill log answers this per repo, not per brand).
   - Big mechanical sweeps → sandbox full-auto or acceptEdits+hooks; consequential
     inceptions → either, plan-gated; parallel disjoint UWs → native subagents favor
     CC, worktree discipline works anywhere.
   - Team habits are real inputs: warm-approval cultures fit Codex's flow; gate-topology
     cultures fit hooks — fit reduces friction, friction breeds bypasses.
3. **Run both, deliberately** (`<h2>`)
   - Three patterns with their receipts: the parity experiment (M20 — free design
     review on consequential epics); cross-engine review (M21 — two authors' theories,
     one set of hunks); split-by-class (each engine owns the classes it enforces
     best).
   - The tax: twin sync (M19's drift), doubled spend, two dialects of muscle memory —
     small teams on simple estates shouldn't pay it.
   - The strategic close: one methodology, many engines — steering files under many
     names (CLAUDE.md, AGENTS.md, Project Rules, Kiro Steering), artifacts both
     engines read, and the lock-in test: "could we switch next bolt?" If no, an
     artifact is missing — find it and write it.

## Recap bullets

1. Claude Code's profile: mechanical enforcement — plan mode, hooks, native
   subagents. Codex's profile: containment and warm review — sandbox, approval
   postures, diff-first flow.
2. Choose per task profile and per what's mechanized in *your* repo today — drill
   logs beat benchmarks, and fit beats fashion.
3. Run both deliberately: parity experiments on consequential epics, cross-engine
   review on risky increments, split-by-class when the tax is worth it.
4. The durable asset is the methodology in files both engines read; the lock-in test
   is "could we switch next bolt?" — if not, write the missing artifact.
