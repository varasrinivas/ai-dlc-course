## Objectives

After this module, the learner can:

1. Set up and launch Codex CLI in the portal repo, and verify AGENTS.md steers it.
2. State what's identical to Track 4 (steering content, the memory hierarchy, the
   rituals) and what differs (enforcement mechanics, approval postures).
3. Map Codex approval modes to Claude Code permission modes and pick the right
   posture for a guardrail repo.
4. Detect and repair steering drift between the twins.

## Hook

The South team joins the portal program — three engineers who've run Codex CLI for a
year and have never opened Claude Code. Their onboarding takes one morning, and the
interesting part is what they *don't* have to learn: the steering file reads the same,
the decision log reads the same, the bolt rhythm and the checkpoints are the ones on
the wall. What they teach the original team by Friday is the other half: Codex's
approval postures, its sandbox, and one drift bug — a rule that existed in CLAUDE.md
and had quietly never been copied into AGENTS.md. Two engines, one methodology; the
methodology traveled. The config almost didn't.

## Concept outline

1. **Codex CLI in five minutes** (`<h2>`)
   - Launch `codex` in the repo; it reads AGENTS.md at start — the same position
     CLAUDE.md occupies (M14's "position is power" applies verbatim).
   - Session shape is familiar: prompt, propose, approve; one UW per session (M16's
     rule is engine-agnostic).
   - What the learner already owns transfers: intent phrasing, plan-first contracts,
     tagged questions, artifact chain by pointer.
2. **AGENTS.md as steering** (`<h2>`)
   - Content-identical twin of CLAUDE.md (M13); the cascade idea holds (global
     ~/.codex config + repo AGENTS.md; nested files for subdirs).
   - What differs is mechanics, not meaning: no plan *mode* (contract instead — M15),
     no hooks (scripts + rules instead — M17); the rules themselves don't change.
   - Drift is the twin-file failure mode: a rule in one file and not the other =
     two teams building under different laws; detect by diff, prevent by
     generate-don't-hand-copy (Lab M13's mechanism).
3. **Approval modes and the sandbox** (`<h2>`)
   - Codex postures: read-only/suggest (propose diffs, human applies) → auto-edit
     (writes files, asks for commands) → full-auto (sandboxed execution) — a dial of
     trust, like Claude Code's default/acceptEdits/plan/bypass but ordered
     differently.
   - Sandboxing: full-auto runs network-disabled, directory-scoped — containment as
     the counterweight for autonomy.
   - Guardrail-repo recommendation: suggest/auto-edit postures + the M17 contractual
     gates; full-auto only for slices the rigor policy classes low-risk.

## Lab outline

**Lab M19 · 25 min · practitioner**

- **Path A — Understand It:** artifact = a diff of the twins with one planted drift
  (CLAUDE.md has the "no Member fields in logs" rule; AGENTS.md lacks it) plus two
  cosmetic engine-name differences. Trace: separate cosmetic from semantic
  differences; predict the concrete behavior divergence the drift causes; propose the
  prevention. 3 check questions + answers.
- **Path B — Build It with AI (both engines):** unit of work — *seat Codex as primary
  and prove the steering holds*. Codex: launch, ask it to restate the three M14
  guardrail rules from AGENTS.md, then run the M14 refusal drill ("set cutoff to
  0.7"); log to docs/M19-parity-drill.md. Claude Code variant: the mirror (restate
  from CLAUDE.md + same drill) appended to the same log. Compare refusals.
  - Verify: both engines restate the same three rules; both refuse the 0.7 request;
    the log captures both. Parity: same rules, same refusal behavior, different
    wording — the module's whole claim, demonstrated.

## Recap bullets

1. Codex CLI reads AGENTS.md at launch exactly as Claude Code reads CLAUDE.md —
   position is power on both engines, and the steering content is identical by design.
2. What transfers untouched: rules, rituals, the artifact chain, checkpoints, session
   hygiene. What differs: enforcement mechanics and trust postures.
3. Codex's dial runs suggest → auto-edit → full-auto (sandboxed); guardrail repos sit
   at suggest/auto-edit with contractual gates.
4. Drift between twins means two laws on one site — diff the twins, and generate
   rather than hand-copy.
