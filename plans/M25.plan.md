## Hook

Bolt 2 is the reason the portal exists and the reason it could end careers: the code
that decides whether a member's imaging request is approved by software or seen by a
nurse. The team treats it accordingly — not with fear, with rigor they already own.
The threshold arrives from the gated config file, never a literal. The PHI-review
stage triggers automatically off the rigor policy. And the test list reads like a
compliance officer wrote it, because in a sense she did: `no_auto_approval_below_
threshold`, `empty_criteria_scores_zero`, `score_log_immutable`. The most dangerous
bolt gets the most boring execution. That's the discipline compounding.

## Concept outline

1. **What bolt 2 builds** (`<h2>`)
   - The ClinicalCriteria entity (criteria sets per serviceCode) and the matcher:
     evaluates a RECEIVED AuthRequest against its criteria set → match score 0.0–1.0
     with per-criterion components.
   - The threshold path: score ≥ AUTO_APPROVE_THRESHOLD (0.85, from config, gated) →
     AUTO_APPROVED status + handoff to B4's determination record; score < 0.85 →
     routing flag B3 consumes (queue entry ≤ 60s, S2 carried).
   - Every score persisted immutably to the compliance store (Priya's closed
     decision) BEFORE any routing occurs — order is an AC, not an implementation
     detail.
2. **The guardrail bolt: maximum rigor, familiar shape** (`<h2>`)
   - Rigor per M10: guardrail class → full pipeline + PHI-review stage (M11) even
     though the code shape is ordinary; the threshold literal appears nowhere but
     the gated config (M17's lock protects it).
   - Negative tests as the spine: no_auto_approval_below_threshold (property-style:
     for scores below threshold, approval is unreachable), exact-threshold decided
     explicitly (0.85 approves — ≥, documented), empty_criteria_scores_zero →
     nurse review, never approve.
   - Explainability: the score log carries components (criterion, weight, matched),
     so "why 0.79?" has an answer a nurse can read — and notification content still
     carries none of it (PHI guardrail from M15).
3. **At the review** (`<h2>`)
   - The no-bypass walk: reviewer traces every code path from scoring to
     AUTO_APPROVED and confirms each passes the threshold comparison — the M08
     understand-every-line discipline with a compliance edge.
   - Immutability proven, not asserted: the test attempts an update and expects a
     loud failure.
   - Bolt close: score-distribution learnings staged for M31's metrics; B3 opens on
     the routing flag contract.
