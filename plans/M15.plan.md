## Objectives

After this module, the learner can:

1. Use Claude Code's plan mode as Inception's natural habitat: the engine reads
   everything and writes nothing until a human approves the plan.
2. Write elaboration prompts that exploit steering context: restate-first, question
   quotas, M05's question tags — short prompts, heavy context.
3. Decompose a Prior Auth intent into units of work end-to-end in the engine, with the
   artifacts landing in docs/.
4. State the parity: what plan mode enforces mechanically in Claude Code, a plan-only
   prompt enforces contractually in Codex — same checkpoint, different enforcement.

## Hook

The notifications epic lands on the team — "members and providers should hear about
determinations without phoning us" — and the PO wants the decomposition by lunch. The
engineer running the session does one thing before typing the intent: switches Claude
Code into plan mode. For the next forty minutes the engine reads the steering file, the
decision log, the semantic map, and bolt 1's close-out; drafts requirements; asks four
tagged questions; and proposes six units of work — and in all that time it *cannot
write a file*. Not "was asked not to." Cannot. The checkpoint isn't a promise in a
prompt; it's a mode the engine is standing in.

## Concept outline

1. **Plan mode: propose without touching** (`<h2>`)
   - What it is: a Claude Code mode where the engine reads, analyzes, and drafts —
     and file writes are off. Enter via shift+tab (or launch with
     `--permission-mode plan`); the engine works read-only until the plan is approved.
   - Why it fits Inception: M05's whole phase produces *proposals*; plan mode makes
     "no artifacts before validation" mechanical instead of behavioral — M07's plan
     checkpoint enforced by the tool itself.
   - Exiting plan mode IS the checkpoint: the engine presents the plan; the human
     approves; only then do writes unlock. Iterating inside plan mode is free —
     chalk, not lumber.
2. **Prompting the elaboration** (`<h2>`)
   - The steering file carries the standards, so prompts stay short and specific:
     intent + output contract + question quota. Restate-first ("restate the intent
     before decomposing"); quotas ("at least 4 clarifying questions, tagged
     [policy]/[edge]/[data]/[integration]"); deferral phrasing ("decisions you won't
     make, listed separately").
   - Context does the heavy lifting: the engine already knows the threshold rule, the
     staleness invariant, the PHI rules — M13/M14's layers earning their keep.
   - Tell for a weak session: questions the decision log already answers — means the
     engine wasn't pointed at the chain (or the chain is stale).
3. **Decomposing the portal intent, worked** (`<h2>`)
   - The notifications epic run: restatement → 5 requirements (incl. PHI guardrail:
     notification content never includes clinical details, only status + reference id)
     → 4 tagged questions → 6 UWs sized by M03's rule.
   - Artifacts land in docs/ (the inception file), reviewed in Mob Elaboration as
     ever; session hygiene: one Inception per session, /clear between epics — context
     is precious (M12's economics).
   - Parity note (one paragraph): Codex runs the same Inception with a plan-only
     prompt contract — same artifact, enforcement by instruction instead of mode;
     M20 goes deep.

Placement: after concept section 2. Cast: North crew, the foreman, Meera & Ravi.
Advances T4: the North crew's job-prep ritual. Draft (≈100 words):

> Before the North crew cut anything for the master stair, they chalked it — full
> size, on the subfloor: every stringer, the landing, the handrail sweep, drawn in
> blue dust exactly where wood would go. The foreman walked Meera and Ravi along the
> chalk lines, adjusting twice on the spot — a longer landing, a gentler sweep —
> each fix costing nothing but a rag and a re-snap. Only when Ravi initialed the

## Lab outline

**Lab M15 · 25 min · practitioner**

- **Path A — Understand It:** artifact = a compressed plan-mode session transcript for
  the notifications epic (mode entered; steering + close-out read; restatement; 2 of
  the 4 questions shown with tags; 6-UW proposal; human trims to 5; approval; mode
  exited; file written). Trace: mark where writes were impossible vs possible; find
  the free iteration; find the question the decision log should have answered (a
  planted flaw — the urgent SLA question was already decided in M06). 3 check
  questions + answers.
- **Path B — Build It with AI (both engines):** unit of work — *Inception on the
  notifications epic*. Claude Code: enter plan mode, prompt with intent + quota +
  tags; iterate once; approve; engine writes `docs/M15-notify-inception.md`
  (restatement, ≥5 requirements incl. the PHI-content guardrail, ≥4 tagged questions,
  UW list with sizing justifications). Codex: identical contract via plan-only prompt.
  - Verify: file structure; PHI guardrail present ("status + reference id only");
    no question duplicates decisions.md; no code. Parity: same artifact; enforcement
    differs (mode vs contract) — and the lab asks the learner to notice it.

## Recap bullets

1. Plan mode is Inception's habitat: the engine reads everything, writes nothing, and
   iterating costs chalk, not lumber.
2. Exiting plan mode is the checkpoint — approval unlocks writes; M07's plan gate,
   enforced by the tool.
3. Elaboration prompts stay short because steering and the artifact chain carry the
   context: restate-first, question quotas, tags.
4. A question the decision log already answers means the engine wasn't reading the
   chain — fix the pointer, not the prompt.
5. Next → M16 · Construction Loops as Sessions.
