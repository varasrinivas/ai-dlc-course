## Objectives

After this module, the learner can:

1. Scope a Claude Code session to exactly one unit of work, and say why (context
   density, reviewable diffs, local failures).
2. Run the in-session loop: read the chain → plan (checkpoint) → build stepwise →
   validate continuously → increment + summary → /clear.
3. Wire scripted gates (syntax checks, tests, lint) so the engine runs and satisfies
   them before presenting work.
4. Recognize session smells — residue answers, two-epic sessions, skipped gates — and
   apply the fix.

## Hook

Two engineers run the same unit of work on the same afternoon. The first opens a fresh
session, points it at the approved plan, and ninety minutes later has a green test run,
a 240-line diff, and an increment summary. The second is on hour five of a session that
has already built UW-1b, debated the eligibility cache, and half-explored a refactor —
and the engine has started confidently referencing a function it deleted two hours ago.
Same engine, same model, same repo. The difference is session hygiene: the first
engineer treats a session like a construction loop; the second treats it like a
workday. Sessions are loops. Bolts are made of them.

## Concept outline

1. **One unit of work per session** (`<h2>`)
   - The rule and its three reasons: context stays dense (M12's economics — the session
     holds one UW's worth of meaning, not a day's residue); diffs stay reviewable
     (M08's understand-every-line needs small increments); failures stay local (a bad
     session costs one UW, not a day).
   - Session start = read the chain (steering auto-loads; plan + decisions by pointer);
     session end = increment merged-or-parked, summary written, /clear.
   - The session is stateless by design (M13): everything worth keeping exits as an
     artifact, so killing a confused session is cheap — and correct.
2. **The loop inside the session** (`<h2>`)
   - The rhythm: plan posted (or resumed from the approved plan) → checkpoint → build
     in steps → validate continuously → present increment with summary.
   - Steering mid-loop is normal: interrupt (Esc), redirect, narrow-block on deferred
     decisions (M02's frozen step 6, now in-tool).
   - Deviation protocol: the engine flags plan departures as it makes them, so Mob
     Construction's deviations-first opening (M08) writes itself.
3. **Gates you can script** (`<h2>`)
   - The engine runs the gates itself — syntax check (node --check style), tests,
     lint — before presenting; a failing gate sends the engine iterating, not the
     human debugging.
   - Wire them low-tech first: "run npx jest and fix failures before showing me
     anything" in the prompt or steering; M17 upgrades this to hooks that make gates
     unskippable.
   - Live example: this course kit — one module per session, injected then gated by
     a validation script; the pattern teaching itself.

## Bridge table

Session-smell table, columns: **Smell / What it indicates / The fix**:
| Engine cites code that no longer exists | Residue: session outlived its context | /clear; resume from artifacts |
| Session has touched two epics | Loop boundary ignored | One UW per session; park the second |
| "Tests pass" but no gate output shown | Gate skipped or hallucinated | Engine runs gates and shows output; M17 makes it unskippable |
| Increment arrives with no summary | Loop exited early | No summary, no review — send it back for the write-up |

## Lab outline

**Lab M16 · 25 min · practitioner**

- **Path A — Understand It:** artifact = two compressed session logs side by side
  (healthy: one UW, 4 gate runs, deviation flagged, clean exit; unhealthy: two UWs,
  a "tests pass" with no output, a reference to a deleted helper, no summary).
  Trace: mark loop stages in the healthy log; list every smell in the unhealthy one

  - Claude Code / Codex variants: identical prompt contract (Codex: plan-only gate

  - Verify: fresh session used; jest green with the PHI-leak test present; gate output

## Recap bullets

1. One unit of work per session: context stays dense, diffs stay reviewable, failures
   stay local — enter reading the chain, leave writing artifacts, /clear.
2. The in-session rhythm is M07's loop made literal: plan, checkpoint, build stepwise,
   validate continuously, present with a summary.
3. Script the gates and make the engine run them — a failing gate sends the engine
   iterating, not the human debugging.
4. Sessions are disposable; artifacts aren't. Killing a confused session is cheap and
   correct.
5. Next → M17 · Checkpoints: Hooks & Validation Gates — making the gates unskippable.
