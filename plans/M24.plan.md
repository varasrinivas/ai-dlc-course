## Concept outline

1. **What bolt 1 builds** (`<h2>`)
   - UW-0 scaffold (stack decision executed — modules per entity, port pattern for
     external systems); UW-1 POST /auth-requests (schema + eligibility + network
     validation, AuthStatus RECEIVED/REJECTED); UW-2 GET /auth-requests/:id (status
     visibility — the M05 provider-visibility epic's first payoff); UW-3 routing
     handoff flag for B2.
   - Every inherited constraint lands in code: collect-all errors (steering),
     staleness-aware eligibility port (I-1), E4 semantics (I-2), outreach log
     structured (M02).
   - Resource naming is contract: `auth-requests`, `members` — the domain anchor is
     API-visible.
2. **The decisions this bolt surfaces** (`<h2>`)
   - Idempotency (bolt-new): duplicate submission (same member+provider+serviceCode,
     open request) → decided: return the existing request id with 200, log the
     duplicate — no second AuthRequest exists.
   - Error contract: 400 with field-level error array (the collect-all rule at the
     HTTP layer, testable); unknown member (the 200-empty-body trap from the
     semantic map) → treated as ineligible, never retried.
   - The eligibility port isolates the 12-year-old system: staleness and E4 live in
     ONE adapter, tested with synthetic fixtures (PHI rule).
3. **At the review** (`<h2>`)
   - Mob Construction watchlist for B1: contract fidelity (paths, statuses, error
     shape), the outreach-log write path (exactly one entry per rejection), the
     AC-to-test trace table, deviations first as always.
   - Bolt close writes: what shipped, the idempotency decision, learnings, and B2's
     open items — the capstone chain grows.
