## Objectives

After this module, the learner can:

1. Hold the plan-only gate contractually in Codex: phrasing, an AGENTS.md standing
   rule as backstop, and recovery when the engine jumps the gun.
2. Run M15's elaboration patterns unchanged in Codex (restate-first, tagged quotas,
   separate deferrals), with suggest posture making even writes proposals.
3. Run the parity experiment: same intent through both engines, compare decompositions,
   and use the differences as review input rather than a verdict.
4. Judge two different-but-valid UW slicings by checkpoint economics.

## Hook

Same Monday, two rooms. North team hands the reporting epic to Claude Code in plan
mode; South team hands the identical intent to Codex under a plan-only contract. By
11:00 there are two inception files on the shared drive. The restatements are
near-identical. The guardrails match. The unit-of-work lists differ by exactly one
boundary — Codex split the export formatter from the aggregation; Claude Code kept
them together. The teams' first instinct is to ask which engine got it right. The
better question — the one the Mob Elaboration actually discusses — is which boundary
gives the humans a better checkpoint. Two independent decompositions for the price of
one prompt is not a consistency problem. It's free review.

## Concept outline

1. **The plan-only contract, mastered** (`<h2>`)
   - The contract's three layers: the prompt clause ("do NOT write; plan and stop for
     approval"), the AGENTS.md standing rule as backstop ("never create files before
     an explicit 'approved'"), and the suggest posture beneath both (writes are
     proposals anyway).
   - Jump-the-gun recovery: if the engine writes early — revert, restate the
     contract, continue; and if it recurs, the standing rule is missing or weak
     (steering bug, not engine flaw).
   - Defense in depth is the honest difference from plan mode: three soft layers
     approximate one hard one; know which layer caught what.
2. **Elaboration prompts in Codex** (`<h2>`)
   - M15's patterns move without translation: restate-first, tagged question quotas,
     separate deferrals, chain-by-pointer; the steering twin carries the standards.
   - The same quality tells apply: zero questions = assumed; a question decisions.md
     answers = the chain wasn't read.
   - Session hygiene identical (M16 is engine-agnostic): one Inception per session.
3. **Decomposition parity as a technique** (`<h2>`)
   - The experiment: one intent, both engines, independently; artifacts named per
     engine; then a comparison pass (either engine writes it).
   - Reading the diff: restatement match = intent is clear; guardrail match =
     steering twins are synced; UW boundary differences = genuine design choices
     surfaced — bring them to the mob as options with rationales.
   - Judging boundaries: M03's sizing rule breaks ties — which slicing gives one
     checkpoint per consequential decision without review-fragment noise?

## Lab outline

**Lab M20 · 30 min · practitioner**

- **Path A — Understand It:** artifact = the two UW lists for the reporting epic
  (CC: 4 UWs, aggregation+formatter together; Codex: 5 UWs, split at the formatter),
  plus each engine's one-line rationale. Trace: check both slicings against the
  sizing rule; identify what the mob should actually decide; write the deciding
  question. 3 check questions + answers (both pass sizing; the real question is
  whether the formatter carries a consequential decision — it does here: report
  columns are compliance-visible → separate checkpoint favors the split).
- **Path B — Build It with AI (both engines):** unit of work — *the parity experiment
  on a fresh intent*: "compliance needs a quarterly outreach report: every rejected-
  at-intake AuthRequest with its outreach status — no member PHI beyond the
  reference id." Run Inception in Codex (plan-only contract) → docs/M20-inception-cx.md;
  run it in Claude Code (plan mode) → docs/M20-inception-cc.md; then either engine
  writes docs/M20-parity-compare.md: restatement match, guardrail match, question
  overlap, UW boundary differences with both rationales.
  - Verify: three files; the comparison table has all four rows; differences framed
    as options, not errors. Parity: the experiment IS the parity check.

## Recap bullets

1. In Codex the plan gate is a contract with three layers — prompt clause, AGENTS.md
   standing rule, suggest posture — and a jump-the-gun means a steering bug to fix,
   not a tantrum to have.
2. M15's elaboration patterns move to Codex without translation; the steering twin
   carries the standards, the chain carries the knowledge.
3. Run the parity experiment on real intents: matching restatements validate the
   intent, matching guardrails validate the twins, and boundary differences are free
   design review for the mob.
4. Judge competing slicings by checkpoint economics — which boundary gives humans the
   better sign-off, not which engine "won."
