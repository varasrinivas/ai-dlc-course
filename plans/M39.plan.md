## Concept outline

1. **One unit through Construction** (`<h2>`)
   - With checkpoints enabled and skeleton on, the engine runs "the first DAG Unit through every
     applicable per-unit stage, including Code Generation, before later Units". For this intent:
     U1 through 3.1 Functional Design, 3.2 NFR Requirements and 3.5 Code Generation (3.3 and 3.4
     were skipped in M37). Show what each writes for U1 (real file list from the capture).
   - Code Generation works in a fixed order: plan (Step 2), the person's Plan Approval (Step 3),
     generation (Step 4), the summary files and `source-manifest.json` (Step 5), review and handoff
     (Step 6). "Never rewrite an approved plan or its test instructions."
   - Where the code lands: the hub's sibling clones (`prior-auth-api/`), on a short-lived branch per
     Bolt, as the team chose in M38. The kit's own practice repos are untouched.
2. **The verified checkpoint** (`<h2>`)
   - `aidlc engine bolt checkpoint --action verify` runs the verification command approved in M38
     and records the result against the unit's fingerprint. "Only a verified checkpoint can be
     approved." Show the real receipt: the command's output for U1, including the guardrail tests.
   - Skeleton vs unit checkpoint: "A skeleton always needs a real" person; an ordinary unit
     checkpoint may be approved automatically only under an explicit autonomous grant. The
     checkpoint is Approve / Request Changes, bound to the current proof; a changed checkpoint
     needs a new one.
   - This is M07's human checkpoint with the evidence attached, and M17's lock in the command:
     the pinned commit, not a moving `main` (the rule the team saved in M38).
3. **Order and parallelism: unit-major, stage-major, swarm** (`<h2>`)
   - New workflows record `Construction Iteration: unit-major` and `Construction Execution:
     serial`: one unit all the way through, then the next. Stage-major runs one stage across all
     units, then the next stage. Swarm "requires stage-major" and fans out eligible Code Generation
     work only "after the skeleton checkpoint is approved"; unit-major "never invokes swarm".
   - The DAG allows U2, U3 and U4 in parallel (M38). The team chose one at a time because the work
     sits next to the 0.85 path. Show the setters (`aidlc engine state
     set-construction-iteration`, `set-construction-execution`) and leave them unchanged.
   - Build and Test (3.6) and the CI pipeline (3.7) run once, after the last unit, not per unit.
     M39 stops before them (open question 3).
   - (Word budget: fig 39.1 carries the comparison, so the prose stays short.)
4. **The autonomy offer, and why it stays off here** (`<h2>`)
   - Skeleton-on offers the choice "after the real skeleton checkpoint": "Continue automatically"
     maps to `aidlc engine bolt set-autonomy --mode autonomous`, "Review each checkpoint" to
     `gated`. "Never infer a grant from silence." Escalation needs a fresh human turn; going back
     to gated doesn't.
   - What autonomy waives (ordinary completion questions) and what it can't: "per-Unit Plan
     Approval, enabled pre-generation summary confirmation, verification command selection,
     skeleton approval, and failures still require the human." On failure the engine always
     halts and asks.
   - Why the course keeps it off for this intent: the command proves the guardrail didn't change;
     it can't judge whether U3's switch or U4's roles are right. That judgment is the checkpoint.
     Contrast with M37: Guard Policy can be locked in memory; autonomy can't (see open question 4).

## Recap bullets

- Construction runs per unit: Functional Design, NFR Requirements and Code Generation for U1 before
  any later unit, because U1 is the walking skeleton.
- Plan Approval comes before any code, for every unit, whatever the autonomy setting.
- The engine runs the team's verification command at each checkpoint and keeps the receipt. Only a
  verified checkpoint can be approved, and the skeleton always needs a person.
- Unit-major and serial is the default. Swarm needs stage-major and an approved skeleton.
- "Continue automatically" waives ordinary checkpoints, not plans or failures. On the threshold path
  the team keeps every checkpoint.
