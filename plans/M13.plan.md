## Objectives

After this module, the learner can:

1. Describe the three-layer memory hierarchy: steering file (standing rules), system
   knowledge (decision log + semantic map), per-bolt artifacts (plans, close-outs) —
   and each layer's change cadence.
2. Explain why sessions are stateless and the artifact chain is not — resuming work
   means reading the chain, not scrolling a chat.
3. State the steering-file pattern across engines: CLAUDE.md (Claude Code), AGENTS.md
   (Codex CLI), Project Rules (Amazon Q Developer), Steering (Kiro) — one pattern,
   many names — and keep two engines' files in sync.
4. Decide what belongs in which layer (a standing rule vs a decision vs a plan step).

## Hook

A new engineer joins the portal team on a Tuesday. By Thursday she ships a send-back fix
to the intake module — not because anyone briefed her for three days, but because the
repo briefed her in ninety minutes: the steering file told her how this team builds,
the decision log and semantic map told her what's true about this system and its crusty
eligibility neighbor, and bolt 1's close-out told her exactly where bolt 2 stands. Then
she asks the question this module answers: "My last team used Codex — do I have to
relearn all of this?" No. The filename changes. The pattern doesn't.

## Concept outline

1. **The memory hierarchy** (`<h2>`)
   - Three layers by change cadence: steering file — how we build here (changes rarely,
     by reviewed edit); system knowledge — decisions.md + semantic map (grows per
     decision/confirmation); per-bolt artifacts — plans, elaboration logs, close-outs
     (one set per bolt).
   - Engines read top-down at session start: steering first, then system knowledge,
     then the current bolt's chain — same order a new human should read.
   - Placement rule: if it applies to every future change, steering; if it's a fact
     about this system, knowledge; if it's about this bolt, plan.
2. **Plan files as durable memory** (`<h2>`)
   - Sessions are stateless on purpose — chat history is not memory; the artifact
     chain is. Killing a session loses nothing that was written down.
   - Resuming = reading: the M09 close-out is the handoff artifact between bolts,
     teams, and even engines — the new-engineer hook is this mechanism working.
   - Anti-pattern: "the AI remembers" — decisions that live only in a transcript are
     M06's undecided-and-unowned, one crash away from gone.
3. **One pattern, many names** (`<h2>`)
   - Say it explicitly: the steering file is one pattern across the industry —
     CLAUDE.md in Claude Code, AGENTS.md in Codex CLI, Project Rules in Amazon Q
     Developer, Steering in Kiro. Learn the pattern once; rename the file per engine.
   - Dual-engine discipline: identical steering content, two filenames; drift between
     them is a silent fork of "how we build" — sync by single-source or copy check.
   - What belongs in steering (conventions, domain rules, guardrails, workflow
     pointers) vs what doesn't (per-bolt state, secrets, anything with a shorter
     cadence than "rarely").

## Lab outline

**Lab M13 · 25 min · practitioner**

- **Path A — Understand It:** artifact = five statements; classify each into its layer
  (steering / knowledge / per-bolt): "collect all validation errors, never fail-fast"
  (steering — convention), "urgent SLA is 4h incl. STAT imaging" (knowledge — decision;
  arguably steering once stable — discuss), "step 6: reject + outreach log" (per-bolt
  plan), "E4 = retro-terminated (confirmed Ortiz)" (knowledge — semantic map),
  "guardrail-or-PHI class always runs full pipeline" (steering — workflow rule).
  3 check questions incl. the promotion path (when does a decision graduate to
  steering?). Answers.
- **Path B — Build It with AI (both engines):** unit of work — *make the two-engine
  memory physical*. Engine reads the existing steering file and (1) generates the
  counterpart for the other engine (CLAUDE.md ↔ AGENTS.md) with equivalent content,
  (2) writes `docs/M13-memory-index.md`: every context artifact in the repo listed
  with its layer and change cadence. Verify: both steering files exist and agree on
  every rule; index covers steering + knowledge + per-bolt; no code.
  - Claude Code / Codex variants: symmetric prompts (each generates the other's file).
  - Parity: after running either variant, the repo steers both engines identically —
    the course's dual-engine claim made physical.
